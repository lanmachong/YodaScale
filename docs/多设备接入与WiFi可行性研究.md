# 体测 App 扩展研究：多设备接入与 WiFi 可行性

调研日期：2026-11-21
适用项目：YodaScale（当前仅支持 Yoda0 / 芯海 OKOK 广播协议）

---

## 一、先给结论

| 问题 | 结论 | 理由 |
|---|---|---|
| 能不能接入更多秤？ | **能，而且比想象中容易** | 市面上绝大多数家用秤集中在 3~4 个协议族，适配 3 个族就能覆盖大半常见品牌 |
| 当前项目支持多设备麻烦吗？ | **中等工作量，架构不复杂** | 加一层「协议适配器」抽象即可，广播型秤可复用现有扫描代码 |
| 要不要做 WiFi？ | **现阶段不建议，优先级低** | 正规 WiFi 秤的 WiFi 只是「上传厂商云」的通道；手机 App 侧几乎都能走 BLE 拿数据，接云端 API 成本高、极易失效且有合规风险 |
| 体脂数据可信吗？ | **Yoda0 不可信，换真阻抗秤才可** | Yoda0 阻抗字段恒为 `5000`，超出有效 BIA 范围（150–1200Ω），体脂率是公式估算 |

## 二、多设备接入：协议族图谱

调研来源：openScale 开源项目（支持 30+ 型号）、ble-scale-sync（23 个适配器）、华为智能秤协议逆向（Peter Maguire）、okok 官方技术说明。

### 2.1 广播型（无需连接）—— 接入成本最低

秤站上后主动把数据塞进 BLE 广播包的 Manufacturer Data，App 只扫不连。当前 Yoda0 就属于这类。

| 协议族 | 典型设备 | 广播特征 | 数据内容 | 难度 |
|---|---|---|---|---|
| **Chipsea / OKOK** | Yoda0、大量贴牌秤、华为低端秤 | Company ID `0x10C0`，13 字节 | 体重 + 阻抗 + 单位/锁定 + MAC | 已攻克 |
| **Xiaomi MIBCS** | 小米体脂秤 1/2、部分米家贴牌 | 广播名 `MIBCS` | 体重 + 阻抗（部分带用户识别） | 低，公开资料充分 |
| **QN-Scale / Renpho** | Renpho、Arboleaf、Senssun、Sencor 等 | 广播名 `QN-Scale` 等 | 体重 + 阻抗 | 低，openScale 已实现 |

**关键洞察**：这几类广播型协议覆盖了亚马逊/淘宝上绝大部分「便宜贴牌体脂秤」。很多看似不同品牌 App（Renpho、Arboleaf）其实共用同一个底层 SDK（`com.qingniu.heightscale`），协议完全一致。

### 2.2 连接型 GATT —— 需要配对、写用户资料

| 协议族 | 典型设备 | 特点 | 难度 |
|---|---|---|---|
| **标准 BLE SIG** | Beurer、Medisana、iHealth、部分华为 | 用标准 `0x181D` 体重服务、`0x181B` 体成分服务 | 低-中，规范公开 |
| **OKOK 连接版** | 高端 Chipsea 秤 | `fff0/fff1` 通知实时体重，`181b/2a9c` 体成分；**秤自己用 App 写入的身高/年龄/性别算体脂** | 中 |
| **华为 Hagrid** | Scale 3 Pro 等 | 私有加密、认证绑定、用户管理 | 高（已有第三方逆向可参考） |
| **FAA0 等加密族** | 部分新款 | AES 加密 + 绑定认证，广播窗口极短 | 高 |

**关键区别**：连接型秤通常要先写用户资料（身高/年龄/性别），否则体脂数据不准或不出。这正好和当前项目新增的「身体资料」功能契合——用户资料已经存本地，接入时可直接复用。

### 2.3 推荐的接入架构

```
ScanCallback（现有）
    └─ 原始广播包
         └─ AdapterRegistry 逐个匹配
              ├─ Yoda0Adapter      （已实现，广播型）
              ├─ MibsAdapter       （下一步，广播型）
              ├─ QnScaleAdapter    （下一步，广播型）
              └─ GattAdapter       （后期，连接型）
                   └─ 统一输出 ScaleReading
                        └─ WeightDb + BodyMetricsCalculator（现有，不用改）
```

适配器接口建议：

```kotlin
interface ScaleAdapter {
    fun match(record: ScanRecord): Boolean   // 用广播名 / Company ID / 数据长度判断
    fun parse(record: ScanRecord): ScaleReading?  // 统一输出，复用现有存储与计算
    val needsConnection: Boolean             // 广播型 false，GATT 型 true
}
```

**实施顺序建议**：
1. 先把 MIBCS 和 QN-Scale 两个广播型适配器加上（各约 100 行代码，参照 openScale 对应 driver）
2. 验证真机（需要借/买对应秤抓一次包确认字段）
3. 再考虑连接型，最后才是加密族

⚠️ 每个新协议**必须有真机验证**。协议文档和实物经常有细微差异（字节序、单位、系数），只看代码不放秤上称一次，很容易出错。

## 三、WiFi 接入分析

### 3.1 WiFi 秤的真实工作方式

调研发现，所谓「WiFi 体脂秤」的数据链路是这样的：

```
秤 ──BLE 配网(写 SSID/密码)──> 手机 App
秤 ──WiFi──> 厂商云服务器 ──> 厂商 App / 微信
```

- WiFi 的作用是**让秤自己把数据上传到云**，这样用户不打开 App 也能同步
- 配网阶段仍然走 BLE（华为 Scale 3 Pro 就是在 `0x1805` 服务下写 SSID 和密码特征）
- App 拿数据有两条路：**BLE 直读**（和现在一样）或**从厂商云 API 拉**

### 3.2 三条可选路线对比

| 路线 | 做法 | 成本 | 稳定性 | 合规/隐私 | 推荐度 |
|---|---|---|---|---|---|
| **A. 只走 BLE（当前方案）** | 忽略秤的 WiFi 功能，手机开 App 时 BLE 直读 | 极低 | 高，不依赖外部 | 数据全在本地，最优 | ⭐⭐⭐⭐⭐ |
| **B. 逆向厂商云 API** | 配网后从云端拉历史数据 | 高：要逆向绑定/鉴权/签名，厂商随时改接口 | 低，接口一变就失效 | 要传数据到第三方，需谨慎 | ⭐ |
| **C. 自己搭云 + 网关** | 用 ESP32 等监听 BLE 广播，自己上传到自有服务 | 中高：要额外硬件和服务器 | 中 | 自己掌控 | ⭐⭐⭐（进阶玩法） |

调研中安全 researchers 已发现多家 OEM 云 API 存在严重漏洞（序列号当密钥、SQL 注入等），说明这类接口既脆弱又不标准——**逆向云端不是个好生意**。

### 3.3 结论与建议

1. **现阶段不做 WiFi**。当前 App 无 INTERNET 权限是刻意设计，物理上杜绝广告和上传，这是它相对 okok 的核心优势，不要为了 WiFi 破坏掉。
2. 如果以后确实需要「不开 App 自动同步」，推荐路线 C（自己的网关 + 自己的云），而不是逆向厂商云。
3. 接入新设备时，**优先选同时支持 BLE 的秤**——几乎所有正规 WiFi 秤都保留 BLE，直接走路线 A 最省事。
4. 若要做 WiFi 研究，建议另起一个独立项目（仓库/目录分开），不要让主 App 背上网络权限的包袱。

## 四、体脂算法说明（供后续适配新秤复用）

当前已实现的估算公式（`BodyMetrics.kt`）：

| 指标 | 公式 | 备注 |
|---|---|---|
| BMI | 体重 / 身高² | |
| 体脂率 | Deurenberg：`1.2×BMI + 0.23×年龄 − 10.8×性别 − 5.4` | 性别男=1女=0；无有效阻抗时的标准估算 |
| 去脂体重 | 体重 × (1 − 体脂率) | |
| 水分 | 去脂体重 × 0.73 / 体重 | |
| 骨量 | 去脂体重 × 0.042 | |
| 肌肉量 | 去脂体重 − 骨量 | |
| 内脏脂肪 | `体脂率×0.55 − 4 + 年龄×0.08` | 限制 1–59 级 |
| 基础代谢 | Mifflin-St Jeor：`10×体重 + 6.25×身高 − 5×年龄 + 5(男)/−161(女)` | |
| 代谢年龄 | `年龄 + (体脂率 − 同龄均值)×0.8` | 同龄均值男 20% / 女 28% |

**注意**：如果后续接入**真阻抗秤**（阻抗在 150–1200Ω 内），应改用 BIA 公式：

```
LBM = c1 × (身高² / 阻抗) + c2 × 体重 + c3 × 年龄 + c4
体脂率 = (体重 − LBM) / 体重 × 100
```

系数（开源项目 ble-scale-sync 整理）：

| 人群 | c1 | c2 | c3 | c4 |
|---|---|---|---|---|
| 男性 | 0.503 | 0.165 | -0.158 | 17.8 |
| 男性（运动） | 0.637 | 0.205 | -0.180 | 12.5 |
| 女性 | 0.490 | 0.150 | -0.130 | 11.5 |
| 女性（运动） | 0.550 | 0.180 | -0.150 | 8.5 |

接入时应优先使用秤自己上报的体成分值（如果有），推算公式只作兜底。
